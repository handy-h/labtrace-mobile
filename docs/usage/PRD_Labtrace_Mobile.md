## 1. 产品概述

### 1.1 产品定位

Labtrace Mobile 是一款面向个人健康管理的移动端应用，专注于医学检验报告与影像报告的**离线管理、趋势跟踪与异常监控**。它作为一个轻量级混合应用（Hybrid App），以 SQLite 为数据核心，通过 WebView 在 Android 设备上运行。

### 1.2 目标用户

| 用户类型 | 典型场景 |
|---|---|
| 个人健康管理用户 | 存储多份体检报告，跟踪各项指标变化趋势 |
| 慢病/长期随访患者 | 管理血糖、血脂、血压等长期检测指标 |
| 陪诊/家庭健康管理者 | 管理多位家庭成员的健康检查数据 |
| 就医复查用户 | 历史检查数据对比，用于医生诊断参考 |

### 1.3 核心价值

- **数据统一管理**：将分散在不同医院的检验/影像报告集中管理
- **跨院对比**：打破医院数据孤岛，支持不同医院历史数据对比
- **全离线可用**：数据存储在本地，无需网络即可使用
- **趋势可视**：直观展示单一指标的历史变化趋势图
- **异常告警**：自动识别偏高/偏低指标，量化健康风险

### 3.2 功能详细规格

#### F1. 报告列表（📋 报告）

| 规格项 | 说明 |
|---|---|
| **触发条件** | 应用启动默认页；点击"报告"标签 |
| **筛选逻辑** | 三个下拉框联动筛选：受检者(ID) → 医院(ID) × 类别(字符串) |
| **数据源** | `lab_reports` 表 JOIN `subjects`/`hospitals`，含 `report_items` 子查询计数 |
| **排序** | 按 `sample_date` 降序（最新在前） |
| **分组展示** | 检验报告（上方）→ 影像报告（下方），带分组标题 |
| **空态** | 显示图标 + "暂无报告数据" + 导入引导 |
| **交互** | 点击卡片 → 对应详情弹窗；PDF 按钮不冒泡点击卡片事件 |
| **影像报告** | 复用卡片样式，展示 `exam_item_name`、`exam_site` 等信息 |

#### F2. 报告详情弹窗

| 规格项 | 说明 |
|---|---|
| **检验报告详情** | 基本信息区 + 检测项目列表 |
| **基本信息** | 受检者、医院、采样日期、类别 |
| **检测项目行** | 项目名称、数值+单位、参考区间、状态徽章(正常/偏高/偏低) |
| **异常判断** | 解析参考区间文本（支持 `"min-max"`、`"<max"`、`">min"` 格式），数值超出则为异常 |
| **影像报告详情** | 基本信息 + 检查描述 + 诊断结果 |
| **弹窗样式** | 底部滑入（slideUp 动画），最大 90vh，大屏居中 |
| **关闭方式** | 点击 × 按钮关闭 |

#### F3. 趋势分析（📈 趋势）

| 规格项 | 说明 |
|---|---|
| **选择器** | 受检者下拉（从 subjects 表加载）→ 检测指标下拉（基于该受检者实际 `report_items` 中的 `test_item_name` 去重） |
| **图表生成** | Chart.js 折线图 |
| **图表元素** | 蓝色主数据线 + 填充区域；绿色虚线(参考下限)；红色虚线(参考上限) |
| **参考区间** | 从第一条数据的 `ref_interval_text` 中正则提取数字区间 |
| **数据表格** | 图表下方同步展示日期/数值/单位/参考区间/状态 |
| **容错** | 无数据时显示空态；无参考区间时仅显示数据线 |

#### F4. 数据检索（🔍 检索）

| 规格项 | 说明 |
|---|---|
| **搜索字段** | 类别、指标名、受检者姓名、医院名称（模糊匹配 LIKE %keyword%） |
| **日期筛选** | 开始日期 + 结束日期，支持单项留空 |
| **触发方式** | 点击"搜索"按钮 或 回车键 |
| **结果** | 复用报告卡片渲染，显示匹配数量 |
| **去重** | DISTINCT 避免因多指标匹配导致同一报告重复 |

#### F5. 统计分析（📊 统计）

| 规格项 | 说明 |
|---|---|
| **前提** | 必须选择受检者 |
| **概览卡片** | 检验报告数、影像报告数、检测项目数、异常指标数四格显示 |
| **时间跨度** | 自动显示该受检者数据的最早 ~ 最晚范围 |
| **异常指标** | 取 flag='high' 或 'low' 的最近 10 条记录，按日期降序排列 |
| **显示** | 项目名、日期、数值/单位、参考区间、↑偏高/↓偏低颜色标注 |

#### F6. 数据导入（📥）

| 规格项 | 说明 |
|---|---|
| **导入内容** | ① SQLite 数据库文件（.db/.sqlite，必选）② PDF 文件集合（可选，多选） |
| **导入流程** | FileReader → `sql.js` 重新实例化数据库 → IndexedDB 持久化 → PDF 缓存到 Map |
| **覆盖策略** | **完全覆盖**：新数据库替换旧数据库，旧数据丢失 |
| **反馈** | 导入状态（进行中/成功/失败），1.5 秒后自动关闭弹窗 |
| **自动刷新** | 导入成功后自动重新加载筛选选项和报告列表 |

#### F7. PDF 查看

| 规格项 | 说明 |
|---|---|
| **渲染方式** | 从缓存的 `pdfFiles: Map<fileName, File>` 中查找，生成 Blob URL |
| **后备方案** | 缓存未命中时直接使用原始 `file_path`（仅在线托管的文件有效） |
| **UI** | 全屏 iframe 渲染，模态弹窗内展示 |
| **限制** | PDF 仅保存在内存中，应用重启后需重新导入 |

## 4. 非功能需求

### 4.1 性能指标

| 指标 | 目标值 | 说明 |
|---|---|---|
| 首次加载 | ≤ 3 秒 | WebView 加载 index.html + 初始化 sql.js WASM |
| 数据库查询 | ≤ 200ms | 含 JOIN 的复杂查询（千级数据量） |
| 趋势图渲染 | ≤ 500ms | Chart.js 渲染 100 个数据点 |
| 数据导入 | ≤ 2 秒 | 1MB SQLite 文件加载 + 持久化 |
| 内存占用 | ≤ 50MB | 正常使用时（含 sql.js WASM ~8MB） |
| PDF 缓存 | ≤ 30MB | 多 PDF 文件 Blob URL 内存占用 |

### 4.2 兼容性要求

| 维度 | 要求 |
|---|---|
| Android 版本 | API 24+（Android 7.0+） |
| WebView 版本 | Chrome 80+ / Android System WebView 80+ |
| 屏幕适配 | 4.7寸 ~ 7寸屏幕，竖屏为主 |
| 网络 | 离线可用（核心功能），仅 PDF 在线查看需要网络 |

### 4.3 安全性

| 项 | 要求 |
|---|---|
| 数据本地化 | 所有健康数据仅存储在设备本地，不上传云端 |
| 存储加密 | [当前未实现] 依赖设备磁盘加密 |
| 文件权限 | Android 6.0+ 运行时动态申请存储读写权限 |
| 隐私合规 | 不收集任何用户个人信息 |

### 4.4 可靠性

| 项 | 要求 |
|---|---|
| 数据一致性 | IndexedDB 持久化确保重启不丢数据 |
| 导入容错 | 文件格式错误时回滚至旧数据库 |
| 降级策略 | sql.js 加载失败时提示用户检查 WebView 版本 |
| 日志 | console 输出调试日志 | 版本发布前关闭调试 |

## 5. 用户交互流程

### 5.1 首次使用流程

```
启动应用
    ↓
sql.js 初始化 → IndexedDB 读取已有数据
    ↓ (首次无数据)
显示"暂无报告数据" + 导入引导
    ↓
用户点击 📥 导入
    ↓
系统文件选择器 → 选择 labtrace.db + PDF 文件
    ↓
导入成功 → UI 自动刷新 → 显示报告列表
```

### 5.2 日常使用流程

```
启动应用 → 报告列表（默认）
    ├─ 筛选受检者/医院/类别 → 列表刷新
    ├─ 点击报告卡 → 详情弹窗 → 查看指标/异常
    │   └─ 点击 PDF → 查看原始检查单
    ├─ 切换到"趋势" → 选受检者/指标 → 折线图 + 数据表
    ├─ 切换到"检索" → 输入关键词/日期 → 搜索结果
    ├─ 切换到"统计" → 选受检者 → 概览卡片 + 异常列表
    └─ 导入新数据 → 覆盖旧数据 → 刷新所有视图
```

### 5.3 异常判断逻辑

```
checkAbnormal(value, refText)
    ↓
┌─ 解析参考区间文本 ──────────────────┐
│  "min-max" 格式 → 数值 < min → low  │
│                  数值 > max → high  │
│  "<max" 格式   → 数值 >= max → high │
│  ">min" 格式   → 数值 <= min → low  │
│  其他/解析失败  → normal            │
└────────────────────────────────────┘
```

## 6. 边界 & 约束

### 6.1 已知限制

| 限制项 | 说明 |
|---|---|
| **单库模式** | 同时只能管理一个 SQLite 数据库，导入即覆盖 |
| **PDF 内存缓存** | PDF 文件仅缓存在应用内存 Map 中，重启即丢失 |
| **无数据同步** | 无云端备份/多端同步能力 |
| **无数据编辑** | 不支持在应用内新增/修改/删除报告或指标 |
| **无用户认证** | 无登录/多用户隔离，数据对所有使用设备的人可见 |
| **无拍照录入** | 不支持拍照识别，仅接受导入已有结构化数据 |
| **依赖 WebView** | sql.js 依赖 WASM，旧版 Android WebView 可能不支持 |

### 6.2 后续版本方向

| 优先级 | 功能 | 说明 |
|---|---|---|
| P0 | 数据导出 | 将当前数据库导出为 .db 文件 |
| P1 | 云端同步 | iCloud/Google Drive 自动备份恢复 |
| P1 | 拍照 OCR | 拍摄检查单照片 → OCR 结构化入库 |
| P2 | 多数据库切换 | 同时管理多位家庭成员的独立数据库 |
| P2 | 指标正常参考曲线 | 按年龄/性别显示通用参考区间 |
| P2 | 健康报告 | 一键生成 PDF 格式健康摘要报告 |
| P3 | 推送提醒 | 定期复查/续查智能提醒 |

### 6.3 风险评估

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| sql.js WASM 加载失败 | 应用完全不可用 | 加载失败时提示升级 WebView / 使用 Chrome |
| IndexedDB 存储上限 | 超大数据库无法持久化 | 约 50MB+ 后可能触发浏览器限制 |
| PDF 文件过大 | 内存 OOM | 单文件建议 ≤ 10MB，暂未实现分页加载 |
| 数据库结构不匹配 | 导入失败或查询异常 | 导入不校验表结构，假设与程序兼容 |
